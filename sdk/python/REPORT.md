# Python SDK report

## Built
`kakitu/` package: signing.py, client.py (retries, idempotency), errors.py (typed, closed code set), models.py, webhooks.py. Tests in `tests/`; fixture `tests/fixtures/go_auth_vectors.json` generated by `go run ./cmd/kakitu-vectors`.

## Verified against Go
- Headers, message format, body hash, "?" only when query non-empty: read from auth/wallet.go.
- Message and signature are byte-identical to Go for all 6 vectors (GET, GET+query, POST body, empty POST, POST+query, unicode body).
- Error codes copied from apiv1/errors.go. Merchant JSON from v1_merchant_c.go. Charge statuses from charge/status.go.
- 23 tests pass.

## Not verified
- `/v1/charges` paths, fields, list shape: do not exist yet (provisional).
- Webhook format/header name: taken from the plan doc only; webhookout not written.

## Surprises
1. Skew window is +-120s; the 300s is the replay TTL. The brief said 300s window.
2. Auth middleware errors use a different envelope: `{"error":"unauthorized","reason":...}`, no request_id. SDK handles both.
3. Idempotency-Key is required on EVERY POST, including POST /v1/merchants.
4. Server signs decoded URL.Path but raw query; SDK mirrors this.
5. Identical request in the same second is a replay, so retries need a new second; SDK waits for it (tests take ~2s for that reason).
6. Three of the four 429 codes are limits, not transient; only rate_limited is retried.
7. Pending merchant may be blocked from charges (merchant_not_approved).
